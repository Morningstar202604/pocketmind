## 二、关键缺陷的复现与修法

### 2.1 MCP 客户端启动崩溃（P0）

复现（真实 stdio 子进程，非 mock）：

```
$ python - <<'PY'
from agentd.mcp import MCPClient
c = MCPClient("self", sys.executable, ["-m", "agentd.mcp_server"])
await c.connect()
PY
AttributeError: 'Tool' object has no attribute 'input_schema'
```

根因：`agentd/mcp.py:_tool_to_dict` 直接读 `t.input_schema`。mcp SDK 1.30 的 `Tool`
是 pydantic 模型，字段名是驼峰 `inputSchema`（`Tool.model_fields` 实测：
`['name','title','description','inputSchema','outputSchema','icons','annotations','meta','execution']`），
没有下划线别名属性。旧单测 `smoke/test_mcp_server.py` 手工构造 dict，从未走过真实 SDK 对象，
所以门禁一直绿。

修法：新增 `agentd/mcp.py:tool_schema()`，按「属性 → alias → dict → `model_dump(by_alias=True)`」
四级取值，缺省返回 `{"type":"object","properties":{}}`；`mcp_client.py` 改用它。
回归：`smoke/p28_mcp_roundtrip_test.py`（真起子进程、真握手、真调用，7 条断言）。

同一次修复也修了 `smoke/test_mcp_server.py` 自身——它读同一个错字段，在 SDK 升级后
会先崩在测试里而不是给出可读断言。

### 2.2 Token 用量不可见（P1）

复现：`curl -N -X POST /api/chat ... | grep done` → `{"type":"done","stop_reason":"end_turn"}`，
没有任何用量字段；`/api/stats` 的 `metrics` 也不存在。

根因：
1. `Agent._stream` 的 OpenAI 直连分支从不传 `stream_options.include_usage`，也从不读 `chunk.usage`；
2. `metrics.record_llm(seconds)` 只记次数与耗时；
3. `metrics.snapshot()` 定义了但全仓无调用方。

修法：
- `agentd/agent.py:_stream` 请求 `stream_options={"include_usage": True}`，端点报 400 时
  自动去掉该参数重试一次（不能让统计把主链路打挂）；解析尾帧 `usage`，写 `self._last_usage`；
- `_stream_round` 把每次调用的 usage 累加到 `self._turn_usage`，并传给 `record_llm`；
- `done` 事件带 `usage`，助手消息 `meta.usage` 落库（刷新后仍可见）；
- `/api/stats` 返回 `metrics.snapshot()`；Prometheus 输出新增
  `pocketmind_llm_prompt_tokens_total` / `pocketmind_llm_completion_tokens_total`。
- mock 模式产出 `estimated: true` 的估算值，格式与真链路一致（避免前端到处写 None 判断）。

回归：`p29`（15 条）+ `p31`（14 条，本地起一个真 OpenAI 协议端点，覆盖文本流、工具调用分片、
usage 尾帧、`stream_options` 被拒时的降级）。p31 是门禁里**第一条不经过 MockLLM 的端到端链路**。

### 2.3 备份只能导不能进（P1）

`/api/export` 的承诺是「完整备份」，但没有对应的导入端点。修法：`POST /api/import`，
合并语义（同 id 会话跳过、知识库按 `(title, content)` 去重、任务默认停用导入、坏文件 400
且不写半截）。实现上刻意避开了一个坑：`Store.set_todos` 会再次获取 `asyncio.Lock`，
而 Lock 不可重入——导入时在持锁状态下直接写 SQL（`agentd/memory.py:import_bundle`）。

## 三、功能补齐（不是修 bug，是补「应该有」）

| 项 | 端点 / 位置 | 说明 |
|---|---|---|
| 会话置顶 | `PUT /api/sessions/{sid} {"pinned":true}` + `sessions.pinned` 列 | 排序 `pinned DESC, updated_at DESC`；只提交 pinned 不会清空标题（p30 有断言） |
| 立即执行任务 | `POST /api/jobs/{jid}/run` | 后台 create_task 起跑，HTTP 立即返回；条件表达式仍生效 |
| 备份恢复 | `POST /api/import` | 见 2.3 |
| 运行统计面板 | 设置 → 运行统计 | 请求数 / LLM 调用 / token / 工具失败；数据来自真实计数器 |
| 消息级用量 | 每条助手消息下方 | 端点未回报时标注「估」 |
